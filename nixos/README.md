# NixOS configuration

Flake-based NixOS config for an HP Pavilion 15-cs2xxx (8 GB RAM, Intel graphics).
Each group in a file starts with a one-line comment, and package lists are
alphabetized within their groups.

| File | What belongs here |
| --- | --- |
| `flake.nix` | Inputs, formatter, and the `nixos` host |
| `flake.lock` | Locked input revisions; update with Nix, never by hand |
| `configuration.nix` | Overlays, boot, hardware quirks, services, desktop session, user, and Nix settings |
| `hardware-configuration.nix` | Generated by `nixos-generate-config`; don't edit |
| `packages.nix` | Desktop, everyday applications, and shell utilities |
| `dev.nix` | Editors, coding agents, languages, language servers, and formatters |
| `fonts.nix` | System fonts |
| `penelope.nix` | Penelope (private repo, `main` branch over SSH) |
| `gaming.nix` | Steam, GameMode, and Gamescope; off until its import is uncommented |
| `opencode-v2.nix` | OpenCode 2, packaged from its npm binary |
| `update-opencode.sh` | Bumps `opencode-v2.nix` to the latest npm release |

Keep custom mounts such as `/mnt/hdd` in `configuration.nix`: regenerating the
hardware file overwrites it.

## Updating

```sh
rebuild   # nixos-rebuild switch with this flake
upgrade   # update every flake input, bump OpenCode, then rebuild
```

Both aliases live in `shell/aliases.sh`, which bash and zsh both source. No input is pinned to a
tag or commit, and every input follows the system `nixpkgs`, so `upgrade`
always moves everything forward. Keep it that way when adding inputs:

- Use a branch, not a tag (`github:owner/repo`, not `github:owner/repo/v1.2`).
- Add `inputs.nixpkgs.follows = "nixpkgs";`.
- A package built from a hardcoded `version` and `hash` won't update on its
  own. Give it an update script, like `update-opencode.sh`, and add that to
  `upgrade`.

New files must be tracked by Git (`git add`) before the flake can see them.

## Maintenance

```sh
nix fmt -- *.nix   # format every Nix file

# Evaluate without building or activating.
nix eval --raw .#nixosConfigurations.nixos.config.system.build.toplevel.drvPath

sudo nixos-rebuild build --flake .#nixos    # build only
sudo nixos-rebuild switch --flake .#nixos   # build and activate
```

- Builds are limited to two jobs with two cores each, to keep the 8 GB laptop
  responsive.
- The store is deduplicated automatically. Garbage collection is manual
  (`clean` alias).
- Leave `system.stateVersion = "26.05"` alone during upgrades. It sets
  compatibility defaults, not the NixOS version.

## Mute-key LED

`configuration.nix` sets `snd_hda_intel model=hp-mute-led-mic3`, the kernel's
[HP mute LED via Mic3 quirk](https://docs.kernel.org/sound/hd-audio/models.html)
for the Realtek ALC295. It routes the speaker mute LED through codec pin `0x1b`.
It's specific to this laptop, so remove it when moving the config to other
hardware.
